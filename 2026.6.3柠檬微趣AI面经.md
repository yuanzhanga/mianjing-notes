什么是BFC，怎么解决浮动塌陷，外边距重叠

**定义**：BFC 是一个独立的布局环境，里面的元素按照块级盒子的规则进行布局，与外部元素相互隔离。

**核心特性**：

- 内部浮动元素会被 BFC 包裹计算高度（解决浮动塌陷）
- BFC 区域不会与外部浮动元素重叠
- 内部两个相邻块级盒子的垂直外边距会发生折叠（但内部与外部不折叠）

**创建BFC**

| 属性值                     | 说明                                 |
| -------------------------- | ------------------------------------ |
| `overflow: hidden`         | 最常用，无副作用                     |
| `overflow: auto`           | 滚动条可能产生                       |
| `display: flow-root`       | 现代浏览器推荐，**专门用于创建 BFC** |
| `float: left/right`        | 元素本身浮动                         |
| `position: absolute/fixed` | 脱离文档流                           |
| `display: inline-block`    | 行内块                               |
| `contain: layout`          | 较新属性                             |

| 问题           | 核心解决                                          | 原理                                     |
| -------------- | ------------------------------------------------- | ---------------------------------------- |
| **浮动塌陷**   | 父元素 `overflow: hidden` 或 `display: flow-root` | BFC 包裹内部浮动，计算高度时包含浮动元素 |
| **外边距重叠** | 给其中一个元素加 BFC 容器，或父元素创建 BFC       | BFC 内外边距隔离，不参与外部折叠         |
| **浮动环绕**   | 非浮动元素创建 BFC                                | BFC 区域不与浮动元素重叠                 |

什么是首屏加载时间，有什么优化方式

**资源体积优化（减少下载量）**

| 手段             | 具体做法                                                     |
| :--------------- | :----------------------------------------------------------- |
| **Tree Shaking** | 移除未使用的代码（ESM + Webpack/Rollup）                     |
| **按需加载**     | `babel-plugin-import` 组件库按需引入                         |
| **图片优化**     | WebP/AVIF 格式、响应式图片 `srcset`、懒加载 `loading="lazy"` |

 **网络传输优化（减少请求耗时）**

| 手段                 | 具体做法                                              |
| :------------------- | :---------------------------------------------------- |
| **HTTP/2 或 HTTP/3** | 多路复用，减少连接开销                                |
| **CDN**              | 静态资源就近分发，降低延迟                            |
| **DNS 预解析**       | `<link rel="dns-prefetch" href="//cdn.example.com">`  |
| **预连接**           | `<link rel="preconnect" href="//cdn.example.com">`    |
| **资源预加载**       | `<link rel="preload" href="critical.css" as="style">` |
| **缓存策略**         | 强缓存（Cache-Control）+ 协商缓存（ETag）             |

**渲染路径优化（减少阻塞）**

| 手段                        | 具体做法                                   |
| :-------------------------- | :----------------------------------------- |
| **CSS 放头部**              | `<head>` 内联关键 CSS，非关键 CSS 异步加载 |
| **JS 放底部或 defer/async** | 避免阻塞 DOM 解析                          |
| **减少重排重绘**            | 避免在首屏执行大量 DOM 操作                |
| **服务端渲染 SSR**          | 直接返回渲染好的 HTML，减少客户端计算      |
| **静态生成 SSG**            | 构建时预渲染，直接输出 HTML                |

**懒加载与按需加载（减少首屏负担）**

| 手段           | 具体做法                                  |
| :------------- | :---------------------------------------- |
| **图片懒加载** | `loading="lazy"` 或 Intersection Observer |
| **路由懒加载** | `React.lazy(() => import('./Page'))`      |
| **组件懒加载** | 非首屏组件动态导入                        |
| **虚拟滚动**   | 长列表只渲染可视区域                      |

**服务端与构建优化**

| 手段               | 具体做法                              |
| :----------------- | :------------------------------------ |
| **SSR/SSG**        | Next.js、Nuxt.js 服务端渲染或静态生成 |
| **边缘渲染**       | Vercel Edge、Cloudflare Workers       |
| **HTTP 缓存**      | 静态资源长期缓存，文件名加 hash       |
| **Service Worker** | 离线缓存，二次访问秒开                |

**衡量工具**

| 工具                            | 用途                            |
| :------------------------------ | :------------------------------ |
| **Lighthouse**                  | Chrome 内置，综合评分和优化建议 |
| **WebPageTest**                 | 多地点、多设备测试              |
| **Chrome DevTools Performance** | 详细分析加载过程                |
| **GTmetrix**                    | 可视化性能报告                  |
